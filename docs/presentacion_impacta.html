Fases del programa

El sistema se divide en tres etapas: el motor físico en C, el almacenamiento en CSV y la visualización en Python.

1Motor en CSimulación física, colisiones y cálculo de energía por tick.
→
2AlmacenamientoExportación a archivos CSV: trayectorias, energía y benchmark.
→
3Visualización PythonGráficas, GIF/MP4 y visor en tiempo real a partir de los CSV.

Separación de responsabilidades: C hace el cómputo intensivo; Python hace el análisis y la presentación. Se comunican solo por archivos CSV.

05

Estructuras de datos

Partícula

typedef struct {
    double x, y;    // posición
    double vx, vy;  // velocidad
    double m;       // masa
    double r;       // radio
} Particula;

Configuración del sistema

typedef struct {
    int    n_particulas, ticks;
    double dt;     // paso de tiempo
    double g;      // gravedad
    double e;      // restitución
    double mu;     // fricción
    double ancho, alto;
} Config;

Las partículas se guardan en un arreglo global Particula p[]. La tabla hash usa dos arreglos: head[] (cabeza por celda) y next[] (lista enlazada de partículas), logrando memoria O(N).

IMPACTA
06

Flujograma del bucle principal

Por cada tick se ejecutan tres sub-bucles en orden:

for (int t = 0; t < conf.ticks; t++) { ... }
A
Bucle A — O(N) · Integración semi-implícita de Euler (gravedad + fricción + movimiento) y rebote con las paredes.
B
Bucle B — colisiones · Detecta y resuelve choques entre partículas. Fuerza bruta sería O(N²); con hashing espacial baja a O(N).
C
Bucle C — O(N) · Suma la energía total del sistema y escribe los datos del instante en los CSV.

Complejidad por tick (fuerza bruta): O(N)+O(N²)+O(N) = O(N²) → total O(T·N²). Con hashing: O(T·N).

IMPACTA
07

Optimización: Spatial Hashing

Antes — O(N²)

Cada partícula se compara con TODAS las demás:

for i in 0..N
  for j in i+1..N
    resolver_colision(p[i], p[j]);

N·(N−1)/2 comparaciones.

Después — O(N)

El espacio se divide en celdas de lado L = 2·max_r y cada partícula solo revisa su celda y 4 vecinas:

cx = floor(x/L);  cy = floor(y/L);
hash = (cx·p1 XOR cy·p2) mod M;
// revisar celda propia + 4 vecinas (K≈5)

~5N comparaciones.

Tabla hash 1D de tamaño M = 12·N → memoria O(N). “En vez de comparar contra todo el universo, cada partícula solo verifica a sus vecinos inmediatos.”

Flujograma de colisión elástica

1Distanciad entre centros de p1 y p2
→
2¿Choque?d < r1 + r2
→
3Normalvector (nx, ny) entre centros
→
4Separarcorrige solapamiento
5Velocidad relativaproyección sobre la normal
→
6Impulsoconservación de momento y energía
→
7Actualizarnuevas vx, vy de ambas

La componente tangencial se mantiene; solo cambia la normal. Las paredes usan reflexión con coeficiente de restitución e.

09

Lógica de la visualización

visualizar.py (archivo)

  • Pre-agrupa por tick con groupby (una sola vez).
  • Un único scatter actualizado por frame (rápido).
  • Menú de estilo: simple / con flechas / flechas + radio.
  • Eje Y invertido → la gravedad cae hacia abajo.

visualizar_realtime.py (en vivo)

  • pyqtgraph + OpenGL: decenas de miles de puntos a ~60 fps.
  • Datos indexados por tick → sin filtrar el DataFrame por frame.
  • Controles: play/pausa, slider, velocidad, submuestreo.
  • Exporta MP4 (más ligero que GIF).

Futuro: para N masivo → vispy / datashader, o render en C (SDL2/raylib) volcando frames a FFmpeg.
